# 2026-10-17

## 数字卡价格：修掉「无随机成分的指数卡」缺分支（商店标价 0）

按用户四步规范逐条核对 `NumberCardInstance.CalculatePowerExpectation`，8 条公式（含骰子/绿色数字的 8 种组合）全部与规范一致，但规范隐含的**第 9 种组合**没有实现：
底数与指数**都不是**骰子、也不是绿色数字（黄金数字不算随机成分），典型资产：

- `2^$10$`(121) `0^$10$`(122) `0^$50$`(123/124) `1^$20$`(125) `1^$75$`(126) `1^$5$`(127)
- `10^$5$`(134) `$5$^$5$`(135) `5^$4$`(136) `5^$3$`(137)

旧代码落到 `else → Debug.LogWarning + return 0`，这 11 张卡在商店**标价 0**。
修法：`else` 改为 `return SignedPow(x, y)`（第一步总原则“不含绿色数字直接算数学期望”，此类卡无随机性，期望即自身输出值）。
修正后价格：2^$10$=122000、0^$10$=11000、$5$^$5$=541000、5^$3$=5420、5^$4$=55800、1^$5$=3000、10^$5$=248000000。

## 另外两处加固（非公式改动）

1. 第二步 `rate` 去掉 `X >= 2` 的下限（规范没有），改为 `X > 0` 才算 `log2(x)-1`；`X == 0`（如 `0^$N$`）时 rate 记 0，只保留黄金数价格。X<2 时价格为负，由第四步统一取绝对值。
2. 价格溢出：`(long)Math.Round(X*rate)` 越界是未定义行为（x64 得 `long.MinValue`），后续 `Math.Abs` 会抛 `OverflowException` → 整卡变 0 价。新增 `ToLongSaturated`（夹 ±1e18）与 `SaturatingAdd`；`RoundPrice` 里 `Math.Abs(long.MinValue)` 也加了保护。`~20~^~20~` 这类极端组合现在饱和到 1e18 而不是 0。

## 资产数据异常（待用户确认，未改）

## hc_check 离线校验工程：本机 NuGet 还原挂了

`dotnet build` 报 `NuGet.targets: error : Value cannot be null. (Parameter 'path1')`（`XPlatMachineWideSetting` → `NuGetEnvironment.CalculateFolderPath` → `Path.Combine(null,…)`）。连 `dotnet new console` 的最小工程也复现，与本项目无关：bash 传给 dotnet 的环境缺 `PROGRAMDATA/APPDATA/ALLUSERSPROFILE`。

可用解法（已跑通）：
```
cd D:\unity\hc_check
PROGRAMDATA="C:/ProgramData" APPDATA="C:/Users/Muwen/AppData/Roaming" ALLUSERSPROFILE="C:/ProgramData" \
  dotnet build --no-restore      # 复用 10-15 生成的 obj/project.assets.json（net10.0）
dotnet bin/Debug/net10.0/hc_check.dll
```
注意：带 `--no-restore` 时不要改 TargetFramework（assets 里只有 net10.0 目标，改 net9.0 会报 NETSDK1005）。
`dotnet msbuild` / `csc` 会被安全策略直接拦截，只能用 `dotnet build`。
新增用例 `TestPowerDeterministicCase`（8 个断言 + 饱和断言），全量 131 项通过。

## 局内存档读取失败修复（根因：初始卡牌不在卡库）

现象：退出后点"继续游戏"，日志先报 `[RunSave] 数字卡资产不存在：2`，随后 `没有可用的局内存档`。

根因（数据核对结论）：
- 场景 `SampleScene.unity` 的 `CardManager.starterNumberCards` = `Assets/prefabs/Library/2,3,4,5,{0},~6~.asset`，`starterFormulaCards` = `Library/StarterCards/InitialFormula.asset`。
- 用 guid 逐个核对：这 7 个资产**均不在** `NumberCardLibrary.asset`（140 条 allCards）/`FormulaCardLibrary.asset` 中。
- 旧 `FindNumberCardData` 只扫卡库 → 返回 null → `ValidateRunSave` 判整份存档无效。

改动（`Managers/RunSaveManager.cs`）：
1. 新增资产索引：`GetNumberCardIndex/GetFormulaCardIndex` = 卡库 ∪ 起始牌组 ∪ `Resources.FindObjectsOfTypeAll<T>()`，`StringComparer.Ordinal`，空名（运行时 CreateInstance 临时资产）跳过；`InvalidateAssetIndex()` 在 `BuildSnapshot` 重建。
2. 校验放宽槽位：允许 `selectedSlotHandIndices` 为空或少于 RequiredCount（未摆牌就退出曾经被判无效）；sceneState=2 仍强制等于 RequiredCount 且全填。
3. 商店价格改 BigInteger 校验（祝福价为 BigInteger，`long.TryParse` 在高回合必误杀）；新增 `IsNonNegativeIntegerString`。
4. 骰子面数合法性 0..1000 校验。
5. `ApplyRun` 调整恢复顺序：先 `ChangeState(PlayerTurn)`/`ShowPanel` 再 `RestoreTurnUI`（未激活面板下重建布局会算错尺寸）；sceneState=2 显式 `ShowPanel(gameUIPanel)`（该路径不走 ChangeState）。
6. `Invalidate` 不再 `ClearSave()`，恢复失败保留存档；`ContinueRun` 区分"无文件"与"校验未通过"并输出路径。

校验：`D:\unity\hc_check` 离线编译 0 错 0 警告，回归 **231 项全过**（新增 6 条存档守卫：起始牌组/兜底扫描/starterFormulaCards/槽位放宽/sceneState=2 仍严格/价格 BigInteger）。

遗留建议（未做，需用户确认）：若希望这 6 张初始卡也能在商店出现，需把它们加进 `NumberCardLibrary.allCards`；本次仅修复读取，不改抽卡池。

## 继续游戏后手牌只剩"随机的几张"（根因：无条件还原槽位）

现象：读档成功，但手牌区只生成存下的少数几张数字卡，不是本回合抽到的全部卡。

实测存档（`LocalLow/DefaultCompany/24亿/runsave.dat`，按 XOR+密钥解出）：
- 库存 6 张（2/3/4/5/{0}/~6~），手牌 `handInventoryIndices = [0,2,1,3]`（4 张），公式 `InitialFormula` 需 4 槽，`selectedSlotHandIndices = [0,1,2,-1]`（已摆 3 张）。
- 旧逻辑在 sceneState=0 也调 `RestorePlacedCardsVisual()`，把那 3 张视图从手牌区搬进槽位 → 手牌区只剩 1 张，看起来像"随机的几张"。

改动：
1. `CardManager.RestoreFromSave`：槽位填装整段包进 `if (d.sceneState == 2)`。未结算存档（0/1）槽位全空（`selectedNumberCards` 保持 null 占位、`filledNumber=0`），全部卡牌留在手牌。
2. `GameManager.RestoreTurnUI(bool restoreSlotPlacements = false)`：只有 true 才调 `RestorePlacedCardsVisual()`。
3. `RunSaveManager.ApplyRun`：sceneState=0 → `RestoreTurnUI(false)`；sceneState=2 → `RestoreTurnUI(true)`（补完结算仍用当时摆好的卡，得分不变）。

回归：hc_check 新增 6 条守卫（仅 sceneState==2 还原槽位 / RestoreTurnUI 开关 / ApplyRun 显式 true-false），编译 0 错 0 警告，**237 项全过**。

## 结算时序重构：点结算后退出 → 当场静默结算并保存，继续游戏才进商店

需求（用户确认）：正常流程照旧自动进商店；若点结算后退出（返回主菜单/关闭游戏），应跳过动画当场算完并保存，点"继续游戏"时进商店，且不能自动弹商店。

根因：`CalculatePoints` 只 `StartCoroutine`，算分/AddPoints/`EndTurn`(OpenShop+切商店)全在协程尾部；`ReturnStartMenu` 只 `ChangeState(MainMenu)` 不停协程 → 协程跑完动画后 `OpenShop()` 把新抽的商店面板盖到主菜单上（"没点继续也刷出商店"）。

改动（`Managers/GameManager.cs`）：
1. 结算状态机字段：`activeSettlementCoroutine` + `settlementDiceSettled / Computed / PointsApplied / Finished / Aborted` + 缓存的 baseScore/totalMultiplier/finalScore；`ResetSettlementState()` 在 `CalculatePoints` 与 `StartPlayerTurn` 调用。
2. 抽出幂等方法：`SettleDiceAndLastRoundMax`（定格+检查点，防二次投骰/递增）、`ComputeSettlementScore`（全部得分与一次性祝福消耗）、`AddSettlementPoints`（坠落/正义+AddPoints）、`FinishSettlementAfterPoints`（隐藏气泡/鬼神境/`EndTurn`/结算完成即落盘）。
3. 协程每个等待点后 `if (settlementAborted) yield break;`；`StopCoroutine(activeSettlementCoroutine)` 只停外层，嵌套靠该标记。
4. `FinishSettlementOnExit()`（public）：Calculation 状态下置 abort、停协程、补算、进商店；仅在真的进入 Shop 时返回 true。
5. `ReturnStartMenu`/`OnApplicationQuit`：Calculation → `FinishSettlementOnExit()`（不再无条件 SaveRun）。
6. `RunSaveManager.SaveSettledRun()`：写 sceneState=1（商店已生成），继续游戏走商店恢复分支，商品不重抽。

回归：hc_check 编译 0 错 0 警告，**250 项全过**（新增 10 条结算时序守卫）。

顺带发现（未改，待用户确认）：①`AddPoints` 内对 hasFall 的负数再×5，而 `AddSettlementPoints` 已×5 → 坠落实际×25；②结算代码里有一段无条件的 `BlessingManager.Instance.RecordRumination(finalScore);` 重复块，拥有反刍时同一回合会记录两次（奖励翻倍）。

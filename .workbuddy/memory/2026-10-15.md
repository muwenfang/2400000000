# 2026-10-15

## 祝福系统三项修复
1. **纯粹容器 / 好事成双 未生效**：两者在 `ApplyBlessingEffect` 的 switch 里根本没有 case（从未实现）。
   - 好事成双（DoubleLuck）：新增 `lastObtainedStackableBlessing` 私有字段，在统一获得入口
     `AcquireBlessing`（新增）里记录"上一个可叠加祝福"（好事成双自身与纯粹容器不计入）；
     购买/获得好事成双时复制该祝福并触发其效果。商店购买、神灯（AddStackableBlessingsToOwned 已改走
     AcquireBlessing）、鬼神境（内部走 TryBuyBlessing）等路径全覆盖。
   - 纯粹容器（PureVessel）：新增 `pureVesselPendingCharges`；`case PureVessel` 只累加待生效次数。
     购买替换逻辑抽成 `TryConvertPurchaseToPureVessel`（TryBuyBlessing 扣费后调用）：按想买的祝福
     扣费，但不入库该祝福，改为入库 1 层纯粹容器（其效果再次待生效→按用户口径会链式替换）。
     买纯粹容器自身不消耗次数；替换所得容器不计入好事成双记录（用户确认的语义：价格=想买的祝福价，
     效果与入库都是纯粹容器）。
   - 新增 `AcquireBlessing(data, triggerEffect, updateDoubleLuckTracker)` 统一获得入口，
     记录更新放在触发效果**之前**（防效果内异常/日志吞掉记录）。
2. **黄色祝福（CurrentRoundOnly：狂赌之渊/唯物主义/流星/慈爱星/启明星/变卖）买后同回合又刷出**：
   根因是 `RefreshShop`/`FreeRefreshShop` 每次刷新都调 `ResetCurrentRoundBlessings()` 清空购买记录。
   改为重置只在 `OpenShop`（新回合进商店）进行；两个刷新函数禁止重置（有源码守卫用例钉住）。
3. **祝福较多时新买的祝福在卡组不显示（效果正常）**：`ShowMyBlessings.OnEnable` 用
   `PlayerCardInventory.InventoryVersion`（卡牌库存版本，买祝福不变）做脏检查导致跳过重建；
   全工程无任何地方调 `RefreshAllBlessings()`。改为 OnEnable 无条件重建（用户选择"只修不显示"，
   不做滚动定位）。

## 教训（已并入 unity-offline-verify skill）
- 反射 Invoke 带默认参数的方法必须显式传全部参数（默认参数不自动填充 → Parameter count mismatch，
  被 try/catch 吞掉后表现为整段假失败）。
- 假 SO 资产的枚举字段默认 0（refreshBehavior=0=AlwaysRefresh），按枚举分支的逻辑必须显式赋值。
- 源码守卫提取方法体：截断点用"下一个 4 空格缩进成员声明"，别用下一个方法签名当锚（顺序易反 →
  负长度 Substring 崩溃）。

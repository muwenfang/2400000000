# 2026-10-01

## 黄金数字的权威数值归属（福星 / 金融专家）

用户反馈：福星应只让"自己手牌里的黄金数字"增加、商店仍显示资产原值；且其他祝福也应能增加黄金数，例如金融专家没生效。

排查结论：
1. `NumberCardInstance.ShouldIncrement` 是**死代码**（定义了但从未被调用），`PrepareForCalculation` 里两处递增判断写的是 `cardData.partA.isIncremental` → 金融专家（`hasFinancialExpert`）从未让黄金数字递增过。这是"金融专家没生效"的直接原因。
2. 福星此前用"克隆 cardData + 删旧加新"实现，虽然不污染库资产，但新建实例会把 `currentA/currentB` 按资产值重置 → 该卡已有的绿色数字进度、`currentDiceSides` 骰子升级全部丢失。
3. 玩家购买商店数字卡时 `AddNumberCard(item.cardData.cardData)` 把**库资产对象直接共享**给玩家实例，所以过去直接写 `cardData.partA.value` 会让商店同款卡一起变。

改动：
- `NumberCardData.cs`：`ShouldIncrement` → 提升为 `public static CanIncrement(NumberComponent)`；新增实例属性 `IsGoldenPartA/IsGoldenPartB/HasGolden`、`GetGoldenValue(partIndex)`、`IncreaseGoldenValue(partIndex, amount=1)`；`PrepareForCalculation` 的两处递增改用 `CanIncrement`（节节高/势如破竹仍只对 `isIncremental` 生效，因为它们的文案是"绿色数字"）。
- `BlessingManager.ApplyFortuneStarEffect`：不再克隆卡牌，改为 `selectedCard.IncreaseGoldenValue(partIndex)`（只改实例当前值）；配套新增 `RefreshOpenNumberCardPanel()`（面板正打开时立即重建）。删除已无用的 `CloneNumberComponent`。
- `BlessingManager` 变卖祝福的黄金数总和改读 `currentA/currentB`（原来是 `cardData.partA.value`）。
- `PlayerCardInventory`：新增 `NotifyCardValueChanged()`（public，供"数值在实例内变化"后自增版本号刷新面板）。

验证：离线工程 `D:\unity\hc_check` 编译 0 错误 0 警告，回归 47 项全通过（新增 14 项黄金数字用例：福星只改实例不动库资产、金融专家递增/连续回合、双黄金卡、绿色与普通数字不受影响）。

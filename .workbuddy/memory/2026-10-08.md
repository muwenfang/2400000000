## 价格公式修正：第一步改为「带符号」求期望（用户口径）
- 规则：第一步**带符号**求和，绝对值只对「第一步的计算结果」整体取一次。用户举例：`2^{0}` → x=(2+4+…+2^9)/9=113.56；`(-2)^{0}` → x=|-2+4-8+…+(-2)^9|/9=38。两者必须不同。
- 改动（`NumberCardData.cs`，只动了指数型分支；非指数型本来就是带符号的）：
  - `CalculatePowerExpectation` 去掉 `Math.Abs`：底数/指数不再取绝对值（`x = a.isDice ? a.diceSides : a.value`），8 个 `return Math.Abs(sum / …)` 全部改为 `return sum / …`，返回有符号结果；
  - 新增 `private static double SignedPow(底数, 指数)`：整数指数走连乘（负底数保留符号），非整数指数才回落 `Math.Pow`——8 处 `Math.Pow` 全部换掉；
  - `GetNumberCardPrice` 保留 `X = Math.Abs(expectation)`，并新增 NaN/Infinity 防御（返回 0 + 警告），避免负指数等极端组合炸掉整个价格计算。
- 影响面：`GetNumberCardPrice` 只有商店两处调用（定价与商品刷新），资产 089–099 号（`(-2)^~6~`、`(-3)^~20~`…）价格显著下降，例如 `(-2)^~6~` 由 215 → 40。
- 验证：离线回归 **82 项全通过**（新增 13 项），含 `(-2)^{0}` 期望 −38、`(-2)^~6~` 期望 7、`(-3)^~8~` 期望 615、`{-2}^1` 期望 3，端到端价格 `2^{0}`=5370、`(-2)^{0}`=485、`(-2)^~6~`=40。
- 过程坑（已记入 skill）：Python 原子改写脚本「校验了匹配数但漏执行」1 处；`return Math.Abs(sum` → `return sum` 留下孤立 `)` 8 处；都是靠编译前 `grep` 逮到。
